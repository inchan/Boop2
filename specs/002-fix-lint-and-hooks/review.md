# Technical Review: 린트 오류 수정 및 Git Hooks 도입

**Date**: 2026-01-02 | **Branch**: `main`

## 1. Multi-Perspective Review

### 1.1 시니어 프론트엔드 아키텍트 (React 패턴 및 상태 설계 관점)

- **리뷰**: `useState` 지연 초기화(Lazy Initialization)를 통해 `useEffect` 내 동기적 `setState`를 제거한 점은 성능 최적화 관점에서 우수함.
- **비판**: `SlateEditor.tsx`의 `setTimeout(..., 0)`은 렌더링 사이클을 임의로 벗어나는 우회책임. `lineCount` 등은 상태가 아닌 파생 데이터(Derived State)로 처리하는 것이 정석임.

### 1.2 DevOps & DX 엔지니어 (개발자 경험 및 자동화 관점)

- **리뷰**: `simple-git-hooks`와 `lint-staged` 도입으로 코드 품질 강제 자동화 체계 구축.
- **비판**: `eslint.config.js`의 전역 변수 수동 관리는 확장성이 낮음. 환경 프리셋(Environment Preset)을 통한 자동화된 타입 추론 환경 구축이 필요함.

### 1.3 보안 엔지니어 (애플리케이션 보안 및 의존성 관점)

- **리뷰**: `crypto.randomUUID()` 사용 및 미사용 변수 관리 강화를 통해 런타임 안정성과 보안성 향상.
- **비판**: 강력한 API(Worker, Crypto) 노출에 대한 린트 제어 외에 실제 런타임 보안 정책(CSP 등)에 대한 고려가 보완되어야 함.

### 1.4 프로덕트 매니저 (서비스 안정성 및 비즈니스 가치 관점)

- **리뷰**: 기술 부채 해결 및 문서화를 통한 팀 생산성 향상.
- **비판**: 기술적 수정이 실질적인 사용자 경험(에디터 응답성 등) 개선으로 이어졌는지에 대한 정량적 근거가 부족함.

### 1.5 주니어 개발자 (코드 가독성 및 온보딩 관점)

- **리뷰**: `prepare` 스크립트를 통한 개발 환경 셋업 자동화는 신규 인원 온보딩에 큰 도움.
- **비판**: 당연한 로직에 대한 불필요한 주석 추가로 코드 노이즈 발생. `setIsLoaded` 미사용 에러 등 작업 완료 전 꼼꼼한 자가 검증이 더 필요함.

## 2. Oracle (코덱스) 심층 기술 리뷰

Oracle로부터 의뢰한 독립적인 기술 리뷰 결과입니다. (2026-01-02)

### 2.1 Critical Issues & Alternatives

| 항목                      | 문제점                                                                                                 | 대안 (추천)                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| **렌더링 우회**           | `setTimeout(..., 0)`을 통한 상태 업데이트는 React 사이클을 벗어난 hack이며 경쟁 조건을 유발할 수 있음. | **Derived State**: `useMemo`를 활용해 에디터 데이터로부터 직접 파생 계산.         |
| **ESLint 설정**           | 20개 이상의 글로벌 변수 수동 정의는 오타 위험이 크고 유지보수가 어려움.                                | **globals 패키지**: `npm install globals` 후 `...globals.browser` 등 프리셋 적용. |
| **죽은 상태(Dead State)** | `isLoaded`가 항상 `true`이거나 사용되지 않아 가독성을 저해함.                                          | **상태 제거**: 지연 초기화(Lazy Init)를 사용하므로 해당 플래그 삭제.              |

### 2.2 Action Plan

1.  **ESLint 고도화**: `globals` 패키지 도입 및 수동 정의 제거 (Quick)
2.  **가독성 개선**: 불필요한 `isLoaded` 변수 및 로직 삭제 (Quick)
3.  **안정성 강화**: `SlateEditor`의 파생 상태(Derived State) 전환 (Short)
