# Feature Specification: 투명도 설정 (Opacity Setting)

**Feature Branch**: `005-opacity-setting`  
**Created**: 2026-01-05  
**Status**: Draft  
**Input**: User description: "설정에 opacity 값을 설정할 수 있게 해서 투명도를 조절하고, 전체 배경(폰트 제외)을 투명하게 표시하여 백그라운드를 볼 수 있도록 해주세요"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 설정에서 투명도 조절 (Priority: P1)

사용자가 설정 화면에서 투명도 슬라이더를 통해 앱 배경의 투명도를 조절할 수 있다. 슬라이더를 조정하면 실시간으로 배경이 투명해지며, 뒤에 있는 화면이나 데스크톱 배경을 볼 수 있다.

**Why this priority**: 이 기능은 사용자가 직접 요청한 핵심 기능으로, 개인화 경험 향상에 필수적이다.

**Independent Test**: 설정에서 투명도 슬라이더를 찾고, 값을 변경했을 때 배경이 투명해지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 설정 화면이 열려있는 상태에서, **When** 투명도 슬라이더를 100%로 이동, **Then** 배경이 완전히 투명해져 뒤의 화면이 보인다.

2. **Given** 투명도가 50%로 설정된 상태에서, **When** 슬라이더를 100%로 이동, **Then** 배경이 더 투명해지고 뒤의 화면이 더 선명하게 보인다.

3. **Given** 투명도가 10%로 설정된 상태에서, **When** 슬라이더를 100%로 이동, **Then** 배경을 포함한 배경 요소들이 완전 불투명해진다.

---

### User Story 2 - 투명도 설정 저장 (Priority: P1)

사용자가 설정한 투명도 값이 앱을 다시 시작해도 유지된다.

**Why this priority**: 일관된 사용자 경험을 위해 설정이 유지되어야 한다.

**Independent Test**: 투명도를 변경하고 앱을 재시작한 후, 설정이 유지되어 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 투명도가 70%로 설정된 상태에서, **When** 앱을 완전히 종료하고 다시 실행, **Then** 투명도가 70%로 유지된다.

2. **Given** 기본값(100%) 상태에서, **When** 투명도를 변경하고 앱 재시작, **Then** 변경된 값이 유지된다.

---

### User Story 3 - 투명도 초기화 (Priority: P2)

사용자가 투명도 설정을 기본값으로 쉽게 초기화할 수 있다.

**Why this priority**: 실수로 잘못 설정한 경우를 복구할 수 있어야 한다.

**Independent Test**: 투명도를 변경한 후 초기화 버튼을 클릭하고, 설정이 기본값으로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 투명도가 30%로 설정된 상태에서, **When** 초기화 버튼을 클릭, **Then** 투명도가 기본값인 100%로 돌아온다.

---

### User Story 4 - 투명도와 테마 상호작용 (Priority: P2)

투명도 설정이 라이트/다크 테마와 모두 정상적으로 작동한다.

**Why this priority**: 테마 기능과 함께 사용할 때 일관된 경험을 제공해야 한다.

**Independent Test**: 투명도를 설정한 상태에서 시스템 테마를 변경하고, 투명도가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 투명도가 80%로 설정된 상태에서, **When** 시스템 테마를 다크에서 라이트로 변경, **Then** 투명도 설정이 유지되며 배경이 투명하게 표시된다.

---

### Edge Cases

- 투명도가 0%일 때 텍스트 가독성 문제가 발생할 수 있는가?
- 투명도가 100%일 때 배경이 완전히 투명해져 UI 요소와 구분이 어려워지는 상황은 어떻게 처리하는가?
- 설정 저장 중 앱이 비정상 종료되면 투명도 설정이 손상되는 경우는 없는가?
- 외부 모니터에서 투명도가 다르게 보일 수 있는가?

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 앱 MUST 설정 화면에 투명도 슬라이더를 제공한다 (10% ~ 100%).
- **FR-002**: 투명도 슬라이더의 변경 MUST 실시간으로 앱 배경에 적용된다.
- **FR-003**: 투명도 설정 MUST localStorage에 저장되어 앱 재시작 시 유지된다.
- **FR-004**: 앱 MUST "투명도 초기화" 버튼을 제공하여 기본값(100%)으로 복구할 수 있다.
- **FR-005**: 투명도 설정 MUST 라이트/다크 테마와 독립적으로 작동한다.
- **FR-006**: 투명도 MUST 배경색에만 적용되고, 텍스트와 UI 요소에는 적용되지 않는다.
- **FR-007**: 앱 MUST 투명도 값이 100%일 때 배경을 완전 불투명하게, 10%일 때 배경을 최소 투명도로 표시한다.

### Key Entities

- **OpacitySetting**: 투명도 설정을 저장하는 데이터 구조
  - `value`: number (10~100, 기본값 100)
  - `updatedAt`: timestamp (마지막 업데이트 시간)

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 사용자가 투명도 슬라이더를 움직이면 배경 투명도가 실시간으로 변경된다 (지연 없음).
- **SC-002**: 투명도 설정은 앱 재시작 후에도 100% 유지된다.
- **SC-003**: 투명도 초기화 버튼은 한 번의 클릭으로 설정을 기본값으로 복구한다.
- **SC-004**: 투명도 설정과 테마 설정은 독립적으로 작동하며, 둘 다 동시에 적용된다.

---

## Assumptions

- 투명도는 CSS `opacity` 속성 또는 `rgba` 색상값의 alpha 채널로 구현한다.
- 100% = 완전 불투명, 10% = 최소 투명도 (기본값 100%).
- 투명도는 배경색에만 적용하고 텍스트는 영향을 받지 않는다.
- Tauri의 투명 윈도우 기능은 사용하지 않고, CSS로만 구현한다.

## Dependencies

- 기존 설정 시스템 (`useSettings` hook, `Settings` 인터페이스)
- 테마 설정 (`004-theme-support`에서 구현된 CSS Variables)
- localStorage를 통한 설정 저장 메커니즘
