# Feature Specification: 탭 그룹(Chrome 스타일) 지원

**Feature Branch**: `011-tab-groups`
**Created**: 2026-01-11
**Status**: Draft
**Input**: 사용자 요청: "브라우저/에디터 탭처럼 같은 주제끼리 수동 그룹핑 + 그룹 접힘 상태 항상 유지 + 색상 + 기본그룹 항상 존재 + 가능하면 DnD"

## Problem
현재 Boop2의 탭은 단일 리스트로만 존재해서, 주제(작업 단위)별로 묶어 보기 어렵고 탭이 많아질수록 탐색 비용이 커집니다.

## Goals
- 사용자가 **수동으로 탭을 그룹**으로 묶어 주제 단위로 관리할 수 있다.
- 그룹은 **접힘/펼침 상태가 항상 유지**된다(앱 재시작/세션 복원 후에도 동일).
- 그룹에는 **색상**을 지정할 수 있다.
- **기본 그룹(Default group)** 은 항상 존재한다(삭제 불가).
- 가능하면 **Drag & Drop(DnD)** 으로 탭을 그룹 간 이동/정렬할 수 있다.

## Non-Goals (이번 스펙 범위 제외)
- 자동 그룹핑(규칙 기반/AI/최근 스크립트 기반 등)
- 탭을 여러 그룹에 동시에 속하게 하는 기능
- 그룹 공유/내보내기/동기화(클라우드)
- 고급 권한/협업 기능

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 그룹 생성/이름/색상 (Priority: P1)
사용자는 주제별로 그룹을 만들고 이름과 색상을 정할 수 있어야 한다.

**Independent Test**: 새 그룹 생성 → 이름 변경 → 색상 변경 → 새로고침/재시작 후 유지 확인

**Acceptance Scenarios**:
1. **Given** 탭이 여러 개 있고, **When** 사용자가 그룹을 생성하면, **Then** 새 그룹이 생성되고 기본 색상이 할당된다.
2. **Given** 그룹이 존재하고, **When** 사용자가 그룹 이름을 변경하면, **Then** 그룹 헤더에 변경된 이름이 표시된다.
3. **Given** 그룹이 존재하고, **When** 사용자가 그룹 색상을 변경하면, **Then** 그룹 헤더(또는 인디케이터)에 색상이 반영된다.

---

### User Story 2 - 탭을 그룹에 할당(수동) (Priority: P1)
사용자는 탭을 특정 그룹으로 옮겨 같은 주제끼리 묶을 수 있어야 한다.

**Independent Test**: 탭을 그룹 A로 이동 → 그룹 A 아래로 렌더링됨 확인

**Acceptance Scenarios**:
1. **Given** 탭 t1이 기본 그룹에 있고, **When** 사용자가 t1을 그룹 A로 이동하면, **Then** t1은 그룹 A에 속한다.
2. **Given** 그룹 A에 탭이 여러 개 있고, **When** 사용자가 탭 순서를 바꾸면, **Then** 그룹 내 순서가 반영된다.

---

### User Story 3 - 그룹 접힘 상태 영속 (Priority: P1)
사용자는 그룹을 접거나 펼칠 수 있고, 그 상태는 항상 유지되어야 한다.

**Independent Test**: 그룹 A 접기 → 앱 재시작/세션 복원 → 그룹 A가 접힌 상태 유지

**Acceptance Scenarios**:
1. **Given** 그룹 A가 펼쳐져 있고, **When** 사용자가 그룹 A를 접으면, **Then** 그룹 A의 탭 목록은 숨겨진다.
2. **Given** 그룹 A가 접혀 있고, **When** 앱을 재시작하면, **Then** 그룹 A는 접힌 상태로 복원된다.

---

### User Story 4 - 기본 그룹은 항상 존재 (Priority: P1)
기본 그룹은 항상 존재하며 삭제할 수 없다. 그룹 삭제 시 해당 그룹의 탭은 기본 그룹으로 이동한다.

**Independent Test**: 그룹 A 삭제 → A 탭들이 기본 그룹으로 이동 확인

**Acceptance Scenarios**:
1. **Given** 기본 그룹이 존재하고, **When** 사용자가 기본 그룹을 삭제하려 하면, **Then** 삭제되지 않는다.
2. **Given** 그룹 A가 있고 탭이 포함되어 있으며, **When** 그룹 A를 삭제하면, **Then** 그룹 A는 제거되고 해당 탭은 기본 그룹으로 이동한다.

---

### User Story 5 - (가능하면) DnD로 이동/정렬 (Priority: P2)
사용자는 DnD로 탭을 그룹 간 이동하거나 그룹 내 순서를 바꿀 수 있다.

**Independent Test**: 탭을 드래그해 그룹 A로 드롭 → 이동/순서 반영

**Acceptance Scenarios**:
1. **Given** 탭 t1이 기본 그룹에 있고, **When** t1을 그룹 A 영역으로 드롭하면, **Then** t1은 그룹 A로 이동한다.
2. **Given** 그룹 A에 탭이 여러 개 있고, **When** 탭 t3을 t2 앞에 드롭하면, **Then** t3이 t2 앞에 배치된다.

---

### Edge Cases
- 그룹 이름이 빈 문자열/공백뿐이면 기본값으로 치환
- 저장된 데이터가 깨졌거나 일부 필드가 누락된 경우에도 앱이 깨지지 않고 최소 상태로 복구
- 존재하지 않는 groupId를 참조하는 탭은 기본 그룹으로 자동 이동
- 접힘 상태/색상은 세션 저장/복원/앱 재시작에서 항상 일관

## Requirements *(mandatory)*

### Functional Requirements
- **FR-001**: 시스템은 탭 그룹을 생성/이름변경/색상변경할 수 있어야 한다.
- **FR-002**: 시스템은 탭을 특정 그룹에 할당할 수 있어야 한다(수동).
- **FR-003**: 시스템은 그룹을 접기/펼치기 할 수 있어야 하며, 접힘 상태는 영속되어야 한다.
- **FR-004**: 시스템은 기본 그룹을 항상 유지해야 하며 삭제할 수 없게 해야 한다.
- **FR-005**: 그룹 삭제 시 해당 그룹의 탭은 기본 그룹으로 이동해야 한다.
- **FR-006**: (가능하면) 시스템은 DnD로 탭의 그룹 이동 및 순서 변경을 지원해야 한다.
- **FR-007**: 기존 로컬 스토리지 저장 포맷(v3: 탭 배열)에서 새 포맷으로 마이그레이션되어야 한다.

### Data Model (Versioned)
- **WorkspaceSnapshot v1**
  - `version: 1`
  - `groups: TabGroup[]` (기본 그룹 포함)
  - `tabs: Tab[]` (각 탭은 `groupId` 포함)
  - `activeTabId: string`

### Storage
- 로컬 저장소(localStorage)에 그룹/탭/활성 탭/접힘 상태/색상이 함께 저장되어야 한다.
- 기존 `boop_current_session_tmp_v3` 기반 데이터는 마이그레이션 경로를 제공해야 한다.

## Success Criteria *(mandatory)*
- **SC-001**: 탭 20개 이상 시나리오에서 사용자가 3초 내 원하는 그룹/탭으로 이동 가능(탐색성 개선).
- **SC-002**: 그룹 접힘 상태가 앱 재시작 후에도 100% 유지됨.
- **SC-003**: 잘못된 저장 데이터가 있어도 앱이 크래시하지 않고 기본 그룹+탭으로 복구됨.
- **SC-004**: 최소 도메인 유닛 테스트가 그룹 이동/삭제/접힘 영속 규칙을 커버함.
